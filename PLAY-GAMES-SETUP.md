# Google Play Games setup and testing

Historical development report. See docs/ANDROID-INTEGRATION.md for fresh integration checks and current limitations.

## Current scope

Achievements, a highest-score leaderboard, and an optional Friends comparison from the post-game local score screen. Cloud saves are excluded. Game Stats is undecided and is not implemented. Morphing remains deferred. Local gameplay, tutorial progress, initials and scores work without Google services, sign-in, or configured IDs.

The Android bridge uses Play Games Services v2 **22.1.0**, pinned from Google's Maven repository. This SDK requires **Android 7 / API 24 or later**, so the prior API 23 floor has been raised to 24. ARM64 and x86-64 remain packaged; target API remains 36.

## What is ready locally

- Existing game events map to the same 12 original Newgrounds medals; Newgrounds behavior remains under its original build flag.
- AWARDS and SCORES actions in the title's bottom row open native Google screens when configured. FRIENDS in the post-game local scores screen opens the native all-time friends leaderboard, after consent if needed.
- Friends comparison uses leaderboard **personal bests**, not an invented feed of friends or a claim that every friend's just-finished run is visible. This game's completed score is submitted before opening the board. A lower run does not replace a higher leaderboard best.
- Earned achievements, best scores, pending work and successful acknowledgements are partitioned by originating Play Games player. A run keeps the identity confirmed when it began; a later profile switch cannot reassign it. Existing local initials/high scores remain a separate device-wide table.
- Runs begun before an identity is confirmed remain unassigned, even if sign-in completes during that run. Opening AWARDS, SCORES or FRIENDS offers a named-profile confirmation before assigning all unassigned history. Keep on device leaves it unassigned; sign-in never assigns it automatically. Older development-build device-wide queues migrate to unassigned history, preserving their originals.
- Only the selected, verified matching profile can upload its own pending work. Pausing invalidates the identity epoch, so stale authentication/upload completions cannot acknowledge another profile's queue. SDK identity is checked again immediately before upload dispatch. Actual SDK account switching still requires live verification.
- F5/F6/F7 debug shortcuts disable platform reporting for that run. Local test scores still work.
- Async platform UI is protected by a foreground/request-generation gate. Home or leaving the requesting game screen cancels pending UI. Native sign-in and friends-consent flows can return to their original request after resume and fresh authentication. An already dispatched upload may complete at Google after pause; its stale callback is ignored and the original owner's pending work remains eligible for an idempotent retry.
- Live access is deliberately disabled with empty Console resources. The SDK's automatic provider is removed; explicit initialization is conditional on real configuration and Google services availability. Missing services or denied sign-in never block replay or local saving.
- Full animated Axol Studio intro is restored on Android, including debug test builds. The shared library normally skips it under debug; a guarded project-local build macro removes only that early exit. Shared axollib files are unchanged.
- Full-intro testing exposed a Flixel 6.1.2 debug bitmap-log bug: clearing the intro's bitmap left a stale selected index and crashed the transition to the title. The same guarded project-local macro resets that index before redraw; shared Flixel files are unchanged. An actual-engine regression reproduced the failure before the fix and passes afterward.
- Icon follows the studio's clarification: an exact reproduction of the existing pixel icon, not the generated illustrated draft. Original 8x8 PNG and archive 64x64 PNG were checked pixel-for-pixel; the archive is an exact integer enlargement. Native vector foreground, Android 8+ adaptive variants, Android 13+ monochrome, and Android 7 fallback are generated by tools/Build-LauncherIcon.ps1. Essential artwork is inside the 66dp safe circle of a 108dp layer. Play listing artwork is artwork/launcher/play-icon-512.png (512x512, RGBA, integer-scaled original pixels with the black frame removed); SVG source is alongside it. Originals are untouched.


## Console setup and verification

No account resources have been created or published by this implementation. Current Console identity and tester configuration require live verification.

1. In the studio's Play Console, confirm the final application package **com.axolstudio.monstermatch** before setting up Play Games. Keep this package stable once credentials are linked.
2. Create or select the game's Play Games Services project. Follow Google's current setup flow and any required OAuth consent-screen steps. Cloud saved games are not part of this task; do not add that feature merely because it appears in Console.
3. Add Android credentials linked to this package and the test signing certificate below. Later, add the separate Google Play App Signing certificate for store-installed builds. An OAuth client ID is not the numeric Play Games project/app ID.
4. Add one numeric, high-score-wins, all-time leaderboard. Use the same score value the game already displays. Provide its Google-generated leaderboard ID.
5. Create the 12 standard, one-time achievements below and provide the Google-generated IDs. Names/descriptions below are working metadata; review wording/XP in Console. Keep original triggers unchanged.
6. Add the intended Google accounts as Play Games testers and ensure the selected Play Games profile/account is one of them. Draft credentials/settings must be available to those testers.
7. Export/copy the real numeric project/app ID, leaderboard ID and 12 achievement IDs into **extensions/play-games/android/src/main/res/values/pgs_ids.xml**. These resource IDs are not passwords; do not send account passwords, private keys, or keystore contents.
8. Rebuild with `./tools/Build-Android.ps1 -RequirePlayGamesConfig`. This rejects empty, partial, or duplicate ID mappings. The ordinary debug build allows an entirely blank configuration for offline testing, but rejects a partially filled one.
9. Live-test on the phone: automatic authentication, cancellation/failure, each award, score submission, public leaderboard, friends consent granted/denied, two actual friend accounts with scores, Home during network requests, account switching, and returning to the game. Do not publish until these are verified.

## Verification commands

- `haxe -cp core -cp tests --main AchievementCatalogTest --interp`
- `haxe -cp core -cp tests --main LocalScoresTest --interp`
- `haxe -cp core -cp tests --main PointerPresentationTest --interp`
- `./tests/PlayGamesConfigTest.ps1`
- Compile UiRequestGate.java and tests/java/com/axolstudio/monstermatch/UiRequestGateTest.java with javac; run the test main class. This covers pending UI on Home, consent/sign-in resume, and canceled screen requests.
- Compile AccountProgress.java, AccountSession.java and tests/java/com/axolstudio/monstermatch/AccountProgressTest.java with javac; run the test main class. This covers A/B isolation, pending/ack persistence, legacy migration, explicit unassigned claims, run ownership and rejected stale account tokens.
- `lime build html5 -debug -D full_intro` checks the full-intro macro independently of Android.
- `lime build html5 -debug -D bitmap_log_regression -D full_intro` exercises adding and clearing an actual debug bitmap; the test page reports `data-log-test="PASS"`. Rebuild the normal game afterward.
- `./tools/Build-Android.ps1` builds the intentional offline/unconfigured test version.

Live SDK results cannot be established with blank IDs or an unlinked signing certificate. Build success and offline UI tests do not establish server authentication, achievement delivery, score acceptance or friends access.

- Android debug build succeeded (ARM64 + x86-64), version 1.0.4 / code 24, min API 24 / target API 36. APK size: 101,969,728 bytes. SHA-256: **354073C55EC3ED649DC4DB6F00242F907D1F22FAE243778D4C70F750DDA46AEB**.
- APK signature and 16 KB ZIP alignment passed; all four packaged ELF libraries have at least 16 KB LOAD alignment. These checks do not substitute for Play upload/pre-launch validation.
- On the isolated official API 30 emulator, updating preserved both existing save files byte-for-byte. Full animated intro reached the title without the previous crash. Original-pixel launcher icon was inspected in the app drawer.
- AWARDS/SCORES/FRIENDS unavailable-service messages returned without blocking play. Touch swapping made a match and increased the score. Android Back paused; Home/return retained the paused run. A debug-forced defeat saved to the local score table and replay worked. The debug run created no Play Games award/score queue, as intended. No HXCPP/AndroidRuntime errors were recorded in this smoke check.
- Achievement mappings, local scores, pointer presentation, configuration validation, UI request lifecycle and account isolation tests pass. Normal HTML full-intro build passes; the actual-engine bitmap-log regression was observed RED before the fix and GREEN afterward. Final review found no Important/Critical issues.
